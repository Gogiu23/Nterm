1. INTRODUCTION                                                 *nterm-intro*

Nterm opens a terminal in a floating window. You can keep several terminals
open and switch between them from a sidebar that shows the last command run
in each one.

The header shows the current terminal (e.g. 2/3) on the left, the title in
the middle, the current mode (NORMAL, INSERT, VISUAL, TERMINAL, ...) on the
right, and a short guide of essential keymaps below.

==============================================================================
2. KEYMAPS                                                      *nterm-keymaps*

Anywhere ~
  <C-/>           Show or hide the floating terminal. Creates one if none
                  exists.
  <leader>gg      Open lazygit (see |nterm-lazygit|).

Inside the terminal ~
  <C-+>           Open a new terminal. Alternative: <C-=>.
  <C->>           Switch to the next terminal (wraps around).
                  Alternative: <C-.>.
  <C-<>           Switch to the previous terminal (wraps around).
                  Alternative: <C-,>.
  <C-b>           Open the sidebar.
  <C-q>           Show a popup with every keymap.
  <Esc><Esc>      Switch from terminal mode to normal mode.

In the sidebar ~
  1-9             Switch to that terminal and close the sidebar.
  <CR>            Switch to the terminal under the cursor.
  <C-+>           Open a new terminal and close the sidebar.
                  Alternatives: <C-=> and +.
  <C-d>           Close the terminal under the cursor (asks first).
  <C-b> q <Esc>   Close the sidebar and go back to the terminal.
  <C-q>           Show a popup with every keymap.

==============================================================================
3. COMMANDS                                                     *nterm-commands*

                                                                *:Nterm*
:Nterm            Show or hide Nterm.
:Nterm lazygit    Open lazygit (see |nterm-lazygit|).
:Nterm {cmd}      Run {cmd} in a new terminal, e.g. `:Nterm btop`. Only
                  <C-/>, <C->> and <C-<> are taken by Nterm there, every
                  other key reaches the program. The terminal closes when
                  the program exits.

                                                                *:NtermHelp*
:NtermHelp        Open this guide.

4. CONFIGURATION                                                *nterm-config*

Nterm works without calling setup(). To change the defaults: >lua

    require('nterm').setup({
      position = 'float',  -- 'float', 'bottom', 'left' or 'right'
      size = 0.3,          -- docked positions: fraction of the editor
      theme = 'auto',      -- 'auto': colors from your colorscheme, 'nterm': built-in palette
      opacity = 1,         -- floating windows, 0..1 (uses 'winblend')
      transparent = false, -- no background: your terminal emulator's transparency shows
      lazygit_key = '<leader>gg', -- false to disable
      border_color = '#2391FF',   -- or { '#from', '#to' }
    })
<
With lazy.nvim: >lua

    { 'Gogiu23/Nterm', opts = { position = 'bottom' } }
<
With 'bottom', 'left' or 'right' the terminal is a split docked to that side
of the editor. The header and the guide are replaced by a single tab on top
of the split with the title, the current terminal and the mode, and the
sidebar opens as a floating window.

Colors ~
With theme = 'auto' (the default) every gradient is built from a highlight
group of your colorscheme, and follows it when you change colorscheme:

    title, NORMAL   Function        VISUAL    Type
    INSERT          String          COMMAND   Number
    TERMINAL        Keyword         REPLACE   DiagnosticError

Groups without a foreground color fall back to the built-in palette, which
you can also force with theme = 'nterm'.

Border ~
The borders of Nterm's floating windows are a gradient running diagonally
from the top-left corner (darkest) to the bottom-right one (lightest).
`border_color` is either one color, whose dark and light shades are used,
or a pair { from, to } with the exact ends. Default: '#2391FF'.

Opacity and transparency ~
`opacity` makes the floating windows see-through (Neovim blends them with
what is behind, needs 'termguicolors'); it doesn't apply to docked splits.
`transparent` removes Nterm's background instead, so the transparency of
your terminal emulator (e.g. Alacritty's `window.opacity`) shows through.

5. LAZYGIT                                                      *nterm-lazygit*

<leader>gg (or `:Nterm lazygit`) opens lazygit in a Nterm terminal, at the
git root of the current file. If lazygit is already running, Nterm switches
to it. Esc, <C-b>, <C-d>... go to lazygit; <C-/> hides it and <C-<> / <C->>
switch terminals. Quitting lazygit (q) closes its terminal.

To open files from lazygit (e) in this Neovim instead of a nested one, add
this to lazygit's config.yml (`lazygit --print-config-dir`): >yaml

    os:
      editPreset: nvim-remote
      edit: >-
        [ -z "$NVIM" ] && (nvim -- {{filename}}) ||
        nvim --server "$NVIM" --remote-send '<C-\><C-n><Cmd>lua require("nterm").edit([[{{filename}}]])<CR>'
      editAtLine: >-
        [ -z "$NVIM" ] && (nvim +{{line}} -- {{filename}}) ||
        nvim --server "$NVIM" --remote-send '<C-\><C-n><Cmd>lua require("nterm").edit([[{{filename}}]], {{line}})<CR>'
      openDirInEditor: >-
        [ -z "$NVIM" ] && (nvim -- {{dir}}) ||
        nvim --server "$NVIM" --remote-send '<C-\><C-n><Cmd>lua require("nterm").edit([[{{dir}}]])<CR>'
<
Editing a file hides Nterm and keeps lazygit running: <C-/> brings it back
where you left it. Outside Neovim the commands fall back to plain nvim.

==============================================================================
6. NOTES                                                        *nterm-notes*

- <C-+> only reaches Neovim in terminals that support the kitty keyboard
  protocol (Kitty, WezTerm, Ghostty, Alacritty). Elsewhere use <C-=> or +.
- The header icon needs a Nerd Font.
- Many terminals send <C-/> as <C-_>; Nterm maps both.
- Inside Nterm, <C-b>, <C-q>, <C-.> and <C-,> are taken by Nterm and don't
  reach the shell.
- The "last command" is read from the prompt line when you press <CR>,
  stripping the prompt up to the first $ > # % or ❯. With unusual prompts
  the whole line may be shown.
